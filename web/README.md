# Khabar web

The unified Next.js frontend for Khabar: the landing page, sign-in, and the doctor, patient and caregiver apps.

```powershell
npm install
npm run dev -- -p 3001
```

Copy `.env.example` to `.env.local` when using Supabase email OTP. The local doctor and patient demos use the API at `http://localhost:8080`.

## The landing page: a storybook film

`/` (`app/page.tsx`) tells Mak Cik Aminah's day in eight scroll-driven acts. The code is in `components/film/`:

| Path | What it is |
|---|---|
| `film-provider.tsx` | Motion on or off (the device's reduced-motion setting and the Pause button), the chosen greeting language, and keeping the reader's place when motion switches |
| `acts/act0-hero.tsx` … `acts/act7-finale.tsx` | One file per act, each with its own GSAP ScrollTrigger timeline |
| `messages.ts`, `product-words.json`, `town.ts` | Every patient-facing word: copied from `PatientMessages.java`, generated by the agents code, or checked against the triage word lists |
| `progress-rail.tsx` | The act rail on desktop |
| `film.module.css`, `tokens.ts` | Styles, colours, easings and breakpoints |

The rules the film keeps:
- **Finished frame first:** the server renders every act's finished frame, and motion only adds to it. Nothing is hidden from screen readers.
- **Pause loses nothing:** Pause and reduced motion stop everything and keep every word.
- **Product words only:** the page never shows words the product would not send.

**Painted backgrounds.** Each act shows a gradient placeholder until its AI art exists. The prompts are in the appendix of `../docs/superpowers/plans/2026-09-28-landing-film-slice.md`. Name the images `act0-desktop.png`, `act0-mobile.png` and so on, then run:

```powershell
node scripts/film-assets.mjs <folder>
```

It writes budgeted AVIF and WebP files to `public/film/` and lists them in `components/film/backdrops.ts`.

## Tests

```powershell
npm run lint
npx tsc --noEmit
npm run test:unit          # the asset pipeline, and every reply shown checked against the triage word lists
npx playwright test        # builds and serves on port 3100, then runs every browser test on desktop and phone
```

Stop anything already on port 3100 first: Playwright starts its own server for a fresh build. If the agents code changes the film's words, regenerate them from `services/agents/` with `.venv/Scripts/python.exe -m scripts.make_film_words`.
